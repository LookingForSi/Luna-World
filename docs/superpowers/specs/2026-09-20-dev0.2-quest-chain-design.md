# Luna World dev0.2 — Quest System + First Quest Chain

Дата: 2026-09-20  
База: `main` / dev0.1 checkpoint  
Целевая ветка: `feature/dev0.2-quest-chain`

## 1. Цель

Добавить первый полноценный server-authoritative quest loop, который связывает уже работающие части Luna World в направленное прохождение:

`Luna Village → Luna Meadows → Stone Circle → Moonfall Road → Goblin Camp → Spider Hollow → Dark Woodland → Ancient Approach → Luna Village`.

Это не narrative system и не branching RPG. Нужна компактная, data-driven и расширяемая quest-система для 5–10 коротких заданий vertical slice.

После реализации новый игрок должен без устных подсказок разработчика понимать, куда двигаться дальше, зачем драться с текущими мобами и когда возвращаться к NPC.

## 2. Scope

Входит:

- persistent quest state;
- DataVersion migration;
- quest definitions;
- server-authoritative accept/progress/turn-in;
- kill objectives;
- talk-to-NPC objectives;
- reach-location objectives;
- prerequisites / последовательная цепочка;
- XP + Luna rewards;
- единый NPC dialogue shell;
- Gatekeeper у стартовой точки, Farmer на ферме и Moonfall Scout;
- интеграция Merchant / Blacksmith в тот же dialogue shell;
- quest tracker;
- открываемая карта мира с player/POI/quest markers;
- quest waypoint / указатель направления к отслеживаемой цели;
- визуальные quest markers над NPC (`!` / `?`);
- визуальные состояния quest topics у NPC;
- reconnect / respawn safe behavior;
- tests и Studio acceptance checklist.

Не входит:

- branching dialogue;
- choices/consequences;
- party-shared quest credit;
- dungeon quests;
- escort objectives;
- item collection quests;
- cutscenes;
- voice/audio;
- procedural/daily quests;
- localization framework;
- Ruins of Selene.

## 3. Основной архитектурный принцип

Quest authority находится только на сервере.

Клиент может:

- запросить разговор с NPC;
- запросить accept/turn-in доступного quest;
- показывать snapshot и tracker.

Клиент не может:

- передать произвольный прогресс objective;
- сообщить серверу, что mob убит;
- сообщить, что location достигнута;
- выдать себе reward;
- завершить quest без server-side validation.

Kill credit приходит только из authoritative `MobService.MobDied`.

Location credit вычисляется сервером по позиции живого персонажа относительно WorldLayout zone/POI contract.

Talk credit фиксируется сервером при валидированном разговоре с NPC.

## 4. Persistence

Quest state становится частью persistent profile. Требуется поднять:

`ProfileSchema.DataVersion: 1 → 2`

и реализовать migration `1 → 2`.

Предлагаемая форма:

```luau
Quests = {
    [questId] = {
        State = "Active" | "ReadyToTurnIn" | "Completed",
        Progress = {
            [objectiveId] = number,
        },
    },
}
```

Отсутствующий quest не хранится. Его доступность выводится из definitions + prerequisites.

Обязательные свойства:

- `createDefault()` создаёт отдельную пустую `Quests`;
- `clone()` deep-clone quest state;
- validator запрещает неизвестные quest IDs / objective IDs, отрицательный progress и невозможные state;
- migration v1→v2 сохраняет весь существующий progression/inventory/equipment и добавляет `Quests = {}`;
- migration tests обязаны проверять v0→v1→v2 и v1→v2;
- текущие сохранения dev0.1 не должны ломаться.

## 5. Data-driven definitions

Создать shared definitions/types, ориентировочно:

- `src/shared/definitions/QuestDefinitions.luau`
- `src/shared/types/QuestTypes.luau`
- при необходимости `src/shared/quests/QuestRules.luau`

Quest definition содержит минимум:

- id;
- displayName;
- description;
- giverNpcId;
- turnInNpcId;
- prerequisiteQuestIds;
- objectives;
- rewardXP;
- rewardLuna.

Objective kinds v0.2:

### KillMob

```luau
{
    id = "kill_young_wolves",
    kind = "KillMob",
    mobId = "mob_young_wolf",
    required = 4,
}
```

### TalkToNpc

```luau
{
    id = "meet_merchant",
    kind = "TalkToNpc",
    npcId = "npc_merchant",
    required = 1,
}
```

### ReachLocation

Location привязывается к существующему `WorldLayout`:

```luau
{
    id = "reach_goblin_camp",
    kind = "ReachLocation",
    poiId = "poi_goblin_camp",
    radius = 90,
    required = 1,
}
```

Допустимо поддержать `zoneId` вместо `poiId`, если реализация получается чище, но definitions должны оставаться data-driven.

## 6. NPC dialogue

В dev0.1 Merchant и Blacksmith уже начинают interaction через `Поговорить`. В dev0.2 это становится общим контрактом для всех NPC.

Нужен единый dialogue shell:

- prompt у NPC всегда: `Поговорить`;
- keyboard: Roblox ProximityPrompt показывает `E`;
- gamepad/touch — фактический binding текущего устройства;
- после prompt открывается `ДИАЛОГ — <NPC>`;
- окно показывает список доступных topics.

Topics могут быть:

- принять quest;
- сдать quest;
- посмотреть незавершённый quest status;
- `Купить`;
- `Продать`;
- `Ковать`.

Merchant:

- Купить
- Продать
- активные/готовые quest topics, если в будущем появятся.

Blacksmith:

- Ковать
- quest topics, если появятся.

Новые NPC:

### npc_gatekeeper — Страж ворот / Gatekeeper

Расположить **непосредственно возле стартовой точки / respawn**, чтобы игрок видел его в первые секунды после появления.

Это первый quest giver. Он отправляет игрока на ферму: оттуда приходят сообщения о неприятностях, и нужно выяснить, что происходит.

### npc_farmer — Фермер

Расположить снаружи фермы в очевидном месте рядом с `poi_farm`.

Q1 завершается **при валидированном входе в диалог с фермером**. Награда Q1 начисляется сразу в этот момент, без отдельной кнопки «Сдать».

После завершения Q1 фермер становится giver следующего задания про молодых волков.

### npc_moonfall_scout — Дозорный Moonfall

Расположить около `poi_moonfall_crossroads` вне опасного aggro-кластера.

Принимает игрока после волчьей части и ведёт по Goblin Camp / Spider Hollow / Dark Woodland.

Не создавать отдельный dialogue UI для quests рядом с EconomyUi. Общая оболочка разговора должна быть одна; специализированные shop/craft screens могут открываться из topic.

### Quest markers над NPC

Quest-aware NPC получают отдельный BillboardGui marker:

- `!` — у NPC есть доступный новый quest;
- `?` — активный quest готов к сдаче этому NPC;
- при отсутствии доступного/готового quest marker скрыт.

Marker должен быть заметнее обычной подписи NPC, но не перекрывать dialogue prompt. Ориентир видимости — около 100–120 studs.

Состояние marker рассчитывается из authoritative quest snapshot, а не из локальной догадки клиента.

## 8. Quest state machine

Минимум:

`Available (derived) → Active → ReadyToTurnIn → Completed`

Правила:

- Accept разрешён только у правильного giver NPC;
- prerequisite quests должны быть Completed;
- один и тот же quest нельзя принять второй раз;
- objective progress capped at `required`;
- после последнего objective server переводит quest в ReadyToTurnIn;
- turn-in возможен только у правильного NPC;
- reward выдаётся ровно один раз;
- после Completed состояние неизменно;
- disconnect / death / respawn не сбрасывают progress.

Одновременно может быть несколько Active quests, но эта первая цепочка линейная.

## 9. Rewards и атомарность

Quest completion reward должен быть idempotent.

XP + Luna + `Completed` должны фиксироваться одним безопасным profile mutation или эквивалентной транзакцией, чтобы повтор remote / reconnect / exception не дал двойной reward.

Для XP использовать `ProgressionRules.applyXP`, не дублировать формулу.

После commit клиентские Level/XP attributes должны синхронизироваться с профилем через нормальный ProgressionService seam. Допустимо добавить публичный метод вроде `ProgressionService.syncFromProfile(player)`, если это чище.

Quest v0.2 не обязан выдавать items — специально оставляем reward transaction XP+Luna-only.

## 10. Location tracking

Не доверять клиенту.

Допустима серверная проверка каждые ~0.4–0.75 секунд только для игроков с активным ReachLocation objective.

Не делать per-frame scan всего мира.

Для POI:

- брать position из `WorldLayout.PointsOfInterest`;
- проверять горизонтальную/3D дистанцию по согласованному контракту;
- credit только живому player character с ready profile.

## 11. Network contract

Нужны отдельные quest/dialogue remotes с schema validation.

Ориентировочно:

Client → Server:

- `DialogueOpenRequest(npcId)` только если действительно нужен отдельный request; ProximityPrompt server event предпочтительнее;
- `DialogueTopicRequest(npcId, topicId)`;
- `QuestAcceptRequest(questId, npcId)`;
- `QuestTurnInRequest(questId, npcId)`;
- `QuestSnapshotRequest()`.

Server → Client:

- Dialogue snapshot;
- Quest snapshot;
- action result / rejection reason.

Любой string ID:

- type checked;
- bounded length;
- lookup in authoritative definitions;
- NPC proximity server-validated.

## 12. Quest tracker UX

Добавить отдельный компактный tracker, не перекрывающий:

- player status;
- target HUD;
- Studio panel;
- combat log;
- action/skill bar.

Показывать максимум 3 active/ready quests.

Для каждого:

- название;
- objective lines;
- `2/4`;
- ready state: `Вернуться к: Староста Луны`.

Tracker должен обновляться после accept, kill/location/talk progress и turn-in без reopen UI.

Mobile: допускается более компактная ширина/шрифт, но tracker не должен механически вылезать за viewport.

## 13. Карта мира и quest navigation

### Кнопка карты

В текущем primary combat/action block добавить кнопку карты по схеме:

```text
[ КАРТА [M] ] [ ИНВЕНТАРЬ [I] ]
[ AUTO       ] [                 ]
[ СБРОС ЦЕЛИ ] [      АТАКА      ]
```

Для keyboard binding — `M`.

На touch показывать просто `КАРТА`. Для gamepad не занимать существующую skill-кнопку; если удобный свободный binding неочевиден, оставить доступ через GUI button до отдельного input pass.

### Map overlay

По нажатию открывается/закрывается большая полупрозрачная top-down карта поверх мира, примерно как modal overlay, а не постоянная minimap в углу.

Карта строится **data-driven из WorldLayout**, без второго ручного набора координат.

Минимально показать:

- Luna Village / spawn;
- Farm;
- Stone Circle;
- Moonfall Crossroads;
- Goblin Camp;
- Spider Hollow;
- Dark Woodland;
- Cemetery / Fallen Shrine;
- Ancient Approach;
- положение игрока;
- текущую tracked quest objective.

Допускается schematic map: terrain texture/рендер не требуется. На dev0.2 достаточно линий/контуров/подписей/точек поверх прозрачной панели.

World → map преобразование должно нормализовать X/Z координаты существующего WorldLayout в размеры map canvas.

### Quest waypoint

Для текущего tracked objective нужен навигационный сигнал вне карты.

Минимальный вариант:

- world-space quest marker / diamond над target NPC или POI;
- расстояние до цели в studs;
- если target за пределами viewport — screen-edge arrow указывает направление.

Не нужен GPS pathfinding по дороге. Достаточно направления к objective.

Для KillMob objective waypoint ведёт к соответствующей encounter/zone точке, а не к конкретному живому экземпляру моба.

### Tracked quest

По умолчанию tracked становится:

- только что принятый quest;
- следующий незавершённый objective внутри него.

Если одновременно активны несколько quests, tracker может показывать до 3, но map/waypoint ведёт к одному selected/tracked quest. Допустимо сделать первый pass с автоматическим выбором самого свежего active quest без ручного переключателя.

## 16. Manual acceptance

Проверить в Studio с новым session profile:

1. spawn в Luna Village;
2. Gatekeeper стоит непосредственно возле respawn и имеет заметный `!`;
3. поговорить с Gatekeeper и принять Q1;

9. `!` / `?` над quest NPC соответствуют authoritative state;
10. kill counter не растёт от чужих/несвязанных событий;
11. reach objectives срабатывают один раз;
12. death/respawn не теряет quest progress/tracked quest;
13. reconnect восстанавливает active/completed quests;
14. turn-in нельзя повторить для двойной награды;
15. tracker/map/waypoint обновляются после перехода к следующей objective;
16. Merchant buy/sell и Blacksmith craft по-прежнему работают из общего dialogue;

18. никаких красных runtime errors.

## 17. Definition of Done

Работа считается законченной только когда:

- реализован весь system scope и Q1–Q7;
- persistence migration безопасна;
- общий NPC dialogue работает;
- tracker работает;
- tests/builds пройдены;
- документация обновлена;
- ветка push'нута в `feature/dev0.2-quest-chain`;
- создан PR в `main`;
- PR оставлен Draft до owner runtime acceptance;
- в Summary отдельно перечислено, что требует ручного Studio acceptance.

Не останавливаться после design/spec или skeleton реализации. Требуется полный implementation pass.
