# План реализации dev0.2 Quest System + First Quest Chain

Дата: 2026-09-20  
Ветка: `feature/dev0.2-quest-chain`  
Design: `docs/superpowers/specs/2026-09-20-dev0.2-quest-chain-design.md`

## Цель

За один implementation pass собрать production-ready quest vertical slice Q1–Q7 поверх текущего dev0.1 без регрессий combat/economy/persistence.

## Этап 1 — persistence contract

1. Расширить `PersistenceTypes.Profile` полем `Quests`.
2. Поднять `ProfileSchema.DataVersion` до 2.
3. Обновить:
   - `createDefault`;
   - `clone`;
   - `validateCurrent`.
4. Добавить migration `1 -> 2` в `MigrationRules`.
5. Обновить migration/profile tests.
6. Проверить, что dev0.1 profile v1 мигрируется без потери Items/Inventory/Equipment/Luna/Level/XP.

## Этап 2 — quest definitions / pure rules

Создать:

- `QuestTypes.luau`;
- `QuestDefinitions.luau`;
- `QuestRules.luau`.

Pure rules должны покрывать:

- derived availability;
- accept;
- objective progress;
- ready transition;
- turn-in eligibility;
- completed state;
- reward application XP/Luna;
- validation helpers.

В definitions сразу внести Q1–Q7 из design.

## Этап 3 — general NPC/dialogue layer

1. Выделить общий NPC interaction contract поверх текущих Merchant/Blacksmith.
2. Добавить `npc_gatekeeper` непосредственно возле respawn/start point.
3. Добавить `npc_farmer` снаружи фермы.
4. Добавить `npc_moonfall_scout`.
5. Все prompts: `Поговорить`.
6. Общая dialogue оболочка показывает topics.
7. Добавить quest markers над NPC:
   - `!` — доступный quest;
   - `?` — ready-to-turn-in.
8. Существующие:
   - Купить;
   - Продать;
   - Ковать
   
   должны продолжить открывать текущий economy flow.
9. Quest accept/turn-in topics добавляются динамически по server snapshot.
10. Q1 должен поддержать auto-turn-in/reward при валидированном открытии диалога Farmer.

Не создавать второй несовместимый набор NPC interaction UI.

## Этап 4 — QuestService

Создать server-authoritative service.

Responsibilities:

- load/snapshot active state from profile;
- accept quest;
- listen `MobService.MobDied`;
- register TalkToNpc;
- poll active ReachLocation objectives;
- transition Active -> ReadyToTurnIn;
- atomic turn-in + reward;
- replicate snapshot;
- lifecycle cleanup.

QuestService не должен считать damage/kill сам — только потреблять authoritative MobDied.

## Этап 5 — network validation

Создать отдельный quest/dialogue network boundary.

Проверить:

- exact argument count;
- types;
- bounded strings;
- authoritative quest/NPC lookup;
- profile ready;
- living player when required;
- proximity to NPC;
- no duplicate accept/turn-in;
- no arbitrary objective update remote.

## Этап 6 — Progression sync seam

Если reward применяется одним profile mutation:

- добавить безопасный public seam в `ProgressionService` для повторной синхронизации Level/XP attributes из persistent profile;
- не копировать progression math в QuestService;
- использовать `ProgressionRules.applyXP`.

## Этап 7 — Quest tracker + navigation

Client UI:

- максимум 3 quests;
- title;
- objectives + progress;
- ReadyToTurnIn hint;
- live snapshot updates;
- compact mobile-safe layout.

Добавить открываемую карту:

- кнопка `КАРТА [M]` в primary action block слева от `ИНВЕНТАРЬ [I]`;
- keyboard binding `M`;
- semi-transparent modal map overlay;
- schematic geometry/POI из `WorldLayout`;
- player marker;
- tracked quest objective marker;
- world→map X/Z normalization.

Добавить quest waypoint:

- target NPC / POI world marker;
- distance;
- screen-edge direction arrow, когда target за viewport;
- KillMob objective направляет к encounter/zone anchor, а не к случайному live mob.

Не перекрывать текущие HUD corners.

## Этап 8 — first chain integration

Пройти Q1–Q7 по definitions:

1. Q1 Gatekeeper → Farmer: “Вести с фермы”, auto-turn-in у Farmer, reward 25 Luna.
2. Q2 Farmer → Young Wolves.
3. Q3 Farmer → Stone Circle pack → Moonfall Scout.
4. Q4 Goblin Camp.
5. Q5 Spider Hollow.
6. Q6 Dark Woodland.
7. Q7 Ancient Approach / Moonbound Warden.

Проверить giver/turn-in NPC routing.

## Этап 9 — tests

Минимум:

- QuestRulesSpec;
- QuestDefinitionsSpec;
- ProfileSchemaSpec updated;
- MigrationRulesSpec updated;
- quest network contract;
- quest server lifecycle;
- dialogue/economy regression;
- tracker contract;
- kill/location authority contract;
- duplicate reward protection.

Запустить существующий test suite; старые regressions не принимать как "не относится к задаче", сначала выяснить причину.

## Этап 10 — build/review

Запустить:

- Luau compile/static checks доступным toolchain;
- `python3 tests/check_*.py`;
- Rojo build default;
- Rojo build test;
- Rojo build world;
- `git diff --check`.

Провести отдельный review:

- persistence/data loss;
- duplicate rewards;
- hostile remotes;
- lifecycle stale callbacks;
- multiplayer state isolation.

## Этап 11 — delivery

1. Обновить CHANGELOG / ROADMAP только фактическим результатом.
2. Commit/push всей реализации в `feature/dev0.2-quest-chain`.
3. Создать Draft PR в `main`.
4. В PR явно отметить:
   - automatic tests;
   - deferred owner Studio acceptance;
   - migration risk;
   - exact Q1–Q7 scope;
   - Gatekeeper/Farmer onboarding;
   - map/waypoint/quest marker acceptance.
5. Не merge'ить PR самостоятельно до owner runtime acceptance.
